# CLAUDE.md

Project rules for this repository. Read on every session; keep it short.

## Where things are written down

`docs/SESSION-LOG.md` is the index: current state, what is open, and what changed when.
Read it first. Reasoning and verified Live behaviours go in `docs/HANDOFF.md`, the spec
in `docs/CONTRACT.md`, durable rules here.

## What this is

An MCP server plus a companion Ableton Live Remote Script that let an LLM read and write
a Live set through Live's Object Model (LOM). General-purpose infrastructure: anyone with
Ableton Live should be able to use it.

Written from scratch. `github.com/ahujasid/ableton-mcp` (MIT, Siddharth Ahuja, 2025) is
prior art we studied and cite in the README — we do not fork it and do not copy its code.
See `docs/HANDOFF.md` for why.

## Hard rules

**The Remote Script is the part that never changes.** Live loads Remote Scripts only at
startup, so every edit costs a full Live restart and a lost session. The script therefore
exposes a small set of *generic* operations over LOM object paths — read a property, write
a property, call a method, read/write notes, run a batch, subscribe to changes — never a
fixed vocabulary of musical verbs. Adding a capability must be a server-side change.

**All intelligence lives in the MCP server.** The Python inside Live is an embedded
interpreter with no third-party packages. Anything that needs real computation, caching,
or libraries belongs in the server process.

**Time is always absolute beats as floats.** Tools accept and return positions and
durations in beats from a defined origin — never bars, never note-value names, never
seconds. Rational subdivisions (triplets, nested tuplets, any n-tuplet) are expressed as
exact floats. This is what keeps the server usable by any note-generating front end.

**Structure is explicit and carried in data.** Clip names, colours, and marker/reference
tracks are first-class parameters, not afterthoughts. Output must be legible to a human
who opens the Live set without having seen the code.

**Batches are atomic.** A batch is scheduled onto Live's main thread once and wrapped in
`Song.begin_undo_step()` / `end_undo_step()`, so a whole sequence collapses into a single
Cmd-Z and cannot leave a half-built set.

**No domain logic in this repo.** Nuzic (the user's music-and-mathematics system) must not
appear anywhere in this codebase — not in code, not in constants, not in comments. It is a
separate project that will consume this server as a client. Nuzic is used only as a
*design reference* when judging whether a tool signature is expressive enough.

**English only** in code, comments, documentation, and commit messages.

**No telemetry.** Not on by default, not opt-out. If usage data is ever wanted it must be
opt-in and documented in the README.

**Bind to 127.0.0.1.** The socket carries unauthenticated control of the user's DAW.

## Message framing

The socket protocol uses newline-delimited JSON (or an explicit length prefix). Never
accumulate bytes and attempt to parse the whole buffer: back-to-back messages concatenate
and the connection dies silently. This is a real bug in the prior art; do not reproduce it.

## Errors

Tools return structured errors, not strings beginning with "Error". A caller must be able
to tell success from failure without parsing prose.

## Environment (verified 2026-07-31)

- macOS, Apple Silicon. Ableton Live 12.4.3 Suite at `/Applications/Ableton Live 12 Suite.app`
- Remote Scripts (user): `~/Music/Ableton/User Library/Remote Scripts/`
  Live also reads `~/Library/Preferences/Ableton/Live 12.4.3/User Remote Scripts/` — use
  only one location; two copies produce duplicate Control Surface entries and a port clash.
- Claude Desktop MCP config: `~/Library/Application Support/Claude/claude_desktop_config.json`
- MCP server logs: `~/Library/Logs/Claude/mcp-server-<name>.log`
- `uvx` at `~/.local/bin/uvx`

Pin the `mcp` dependency to `<2`. Version 2.0.0 removed `mcp.server.fastmcp`; an unpinned
`mcp[cli]>=…` resolves to 2.x and the server dies at import before registering any tool.

## Development loop

Editing the Remote Script requires quitting and reopening Ableton Live. Editing the server
does not. If a session needs many Live restarts, logic is being placed on the wrong side of
the boundary — move it to the server.

Verify against a real Live instance, not only unit tests: the LOM is undocumented and
version-dependent. Write a property, read it back, compare.

## Before implementing anything new against the LOM

Check `docs/lom-inventory.md` (generated by runtime introspection inside Live) rather than
assuming an API exists. If it is not in the inventory, verify it before designing around it.
